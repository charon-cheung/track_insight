# 多轮测试报告归档设计

用户已确认“测试总览主页 + 每轮独立报告”，本轮直接实施。

## 目标与边界
- 总览提供轮次表格和下拉选择，按测试开始时间倒序；每轮独立保存 report.html、analysis.json、指标与图片。
- 全部通过本地 file:// 打开，无服务器、无外网、无新依赖。
- 首页显示轮次名称、时间、case 数、平均横向 RMSE、整体 RMSE、覆盖率、最差 case 与备注；沿用 makeOverview 口径，failed/replaced 不纳入均值，缺失值不作零。
- 不改变单轮指标、bag 读取或现有报告模式；不做跨轮曲线叠加。

## 方案选择
用户选择独立总览与独立报告。一个巨大 HTML 会重复加载全部轨迹，单纯手动维护文件夹缺少统一入口；采用轻量索引和每轮独立文件夹。

## 实现决策
- 保留 --output DIR 原有语义。analyze/render 新增 --archive DIR，与 --output 互斥；--name/--note 仅适用于归档。
- archive/index.html 为入口，runs.json 为轮次索引，runs/<稳定轮次 ID>/ 为单轮目录。
- 同一 bag 内容 SHA256 对应同一轮，记录时间加哈希前缀用于目录命名；同秒不同内容不会覆盖。同一文件重新分析需 --replace，仅替换该轮，保留其他轮；未指定名称/备注时沿用已有值。
- 轮次名称默认使用 bag 名称；参数 --name/--note 可持久修改名称备注。现有 analysis.json 可用 render --archive 导入，无需重新读 bag。
- 归档报告增加“测试总览”返回链接。单轮 --output 生成的报告保持原样。
- 专用 archive.cpp/hpp 负责归档身份、索引、写入事务；不向现有指标模块添加归档职责。
- 加锁、暂存、发布失败回滚；拒绝非归档目录、符号链接和不受管理的目标文件；不自动接管已有单轮目录。
- runs.json/首页始终只包含生成完毕的轮次；图片部分失败保留原有 partial 状态。
- 使用相对链接，整个归档目录可移动；复制同一 bag 为 ZIP 与目录可能有不同输入哈希，视为不同来源，不猜测合并。
